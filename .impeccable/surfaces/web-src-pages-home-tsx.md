Scope: Repository creation, empty-repository setup, and storage-based plan presentation. Mode: Operate.

Audience: developers creating or importing a project. Job: choose an owner and a durable repository identity, decide visibility and initial files, then reach a useful working repository without uncertainty. Primary action: create the repository. Constraints: preserve Flurry's existing compact white and soft-blue shell, support personal and manageable organization ownership, keep all product language native to Flurry, and remain usable on mobile and keyboard.

## Direction contract

THESIS: A familiar, low-friction creation form that shows the resulting repository identity before submission and turns an empty project into an immediately actionable setup page.

OWN-WORLD: Flurry's restrained blue, fine neutral rules, square-soft corners, compact sans-serif typography, and information-dense forms. Selection states use borders and quiet surface changes rather than decorative cards.

STORY: The developer picks an owner and name, sees the resulting path, adds optional context, makes one clear visibility choice, optionally prepares the first commit, and creates. An initialized repository opens on its files; an empty repository opens on copyable local setup commands and an import path.

FIRST VIEWPORT: The title, import alternative, owner/name identity row, description, and visibility choices are visible without an oversized introduction. Initialization is a secondary section, while the create action stays visually decisive.

FORM: Scoped extension of the established product UI. Seed key: repository-start.

FINISH: complete only after desktop and mobile review, keyboard and state checks, the Impeccable detector, and updated product documentation.

Unresolved: none.
